## Ownership and lifetime

Wait and Release Wait close the owned control menu automatically. The game pump revalidates
the captured actor FormID, base form, plugins, playthrough and cancellation generation. There
are no companion, faction, hostility, combat or scene exclusions for the wait pair; dead,
disabled, deleted or unloaded references are not executable actors.

The native adapter clears its own previous wait instance, stops combat, and starts waits with
`Actor::PutCreatedPackage(wait, true, false, true)`:
run-once slot, authored/non-temporary record, allowed from furniture. It uses
`AIProcess::SetRunOncePackage(nullptr, actor)` only to release its own wait. Both are guarded
for Fallout 4 1.11.240.0: Address Library IDs 2230002 / RVA C81C00 and 2232344 / RVA D34620.
It reads ownership under a
nonblocking package lock and drops that lock before the engine call. No network, file reads,
arbitrary script dispatch or actor mutation occurs in the renderer.

Release clears only the SYNTH run-once package. It never clears a replacement owned by another
mod and does not set AI-disable, paralysis, speed, restraint or companion actor values.
Normal package selection resumes; an interrupted third-party run-once package is not replayed.
Another mod can still explicitly replace SYNTH's package. The command stays suspended while
another run-once or a transient/scene package owns the actor; recovery never overwrites that slot.

The engine package has no timeout. A bounded, menu-free game-pump sweep
releases cancelled leases and orphaned SYNTH packages restored from saves. Only numeric
handles, copied positions, timestamps and cancellation tokens survive between pumps. Unloaded actors are cleaned when they
become observable again. There are at most 256 owned leases; discovery checks at most 32 high
and 32 middle-high handles per second. Runtime save/load invalidates the session token, so an
old lease cannot authorize a new wait. SYNTH adds no co-save records or server state; the engine
may serialize its run-once package normally.

This preserves SYNTH's generation invalidation boundary: save/load or hard halt releases the
old wait. It does not yet reproduce Dialectic's persistent cross-generation wait state.
At five seconds, then every thirty seconds, the log records ownership, procedure index and
distance from the original command position. Package replacement suspends, rather than discards,
the command. A menu-free sweep restores it only when run-once is empty and the base package is
ordinary (type 18) or absent, with no active dialogue/scene/combat/posture transition. Initial
recovery has a one-second debounce; failed restoration attempts are spaced at least two seconds
apart. Release Wait cancels both active and suspended commands. No recovery calls StopCombat.

The engine recaptures its package-start location on recovery. Diagnostics retain the original
command position so drift remains visible; this does not teleport an actor back if a scripted
interaction moved them. A permanent original-position anchor is not implemented.

## Manual acceptance still required

1. Launch manually with `SYNTH.esp` enabled. Open the configured Control hotkey on Preston.
2. Choose Wait Here; confirm the menu closes, the NPC stays put, and SYNTH.log records the
   exact actor and installed package. Reopen and choose Release Wait; confirm normal movement.
3. Repeat for an ordinary settler, hostile/combat actor and scripted-scene actor. Confirm speech
   and subtitles continue; installation acknowledgement is not proof of stopped movement.
4. Verify waiting beyond five minutes, hard halt, travel/unload/reload, and loading a save made while waiting.
5. Confirm no changes to voice configuration, hotkeys, saves or unrelated plugins.

This task builds/deploys flat only. VR wait support remains explicitly unsupported.

disappearing at 12:00:05 and 12:01:08. The old adapter erased its lease at that point.
